<!-- sdlc:auto:start overview -->
Performance management System (PMS) is a two-application repository generated by the Quorq AI SDLC platform. The frontend is a Vite + React 19 single-page app in TypeScript, styled with Tailwind CSS v4. It uses React Router 7 for routing and TanStack Query for server state. It has a sign-in screen and five signed-in screens inside a side-menu shell: My performance, Goals, Reviews, 1:1 check-ins and People. The backend is a FastAPI 0.115 service using SQLAlchemy 2 and Alembic migrations. It currently implements cookie-based authentication (`/auth/login`, `/auth/logout`, `/auth/me`), HR-admin employee management (`/employees`), lookup lists (`/departments`, `/job-titles`) and a `/health` probe. The database defaults to a local SQLite file (`app.db`) and switches to PostgreSQL via `DATABASE_URL`. The frontend calls the API through `src/lib/api.ts`, which sends the session cookie and adds an `X-Requested-With: pms` header on mutations. Note that the top-level README says the backend has only a health check, but the code shows more. The frontend README says screens run on seeded sample data, so check each screen before assuming it is wired to the API. Pushes to `main` deploy through GitHub Actions: the API image goes to AWS ECR and the frontend bundle to AWS Amplify.

<!-- sdlc:auto:start prerequisites -->
- Python 3.12 (the backend Dockerfile uses python:3.12-slim)
- Node.js with npm (no version is pinned in package.json; it must be recent enough for Vite 6 and React 19)
- Docker with Compose (optional), to run the PostgreSQL 16 and Redis 7 services in docker-compose.yml
- Playwright Chromium (installed via `npm run test:e2e:install`), only needed for end-to-end tests
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. Clone the repository and change into it.
2. (Optional) Start PostgreSQL and Redis: `docker compose up -d`
3. Create the backend virtualenv (the Playwright config expects it at backend/.venv): `cd backend && python -m venv .venv && .venv/bin/pip install -r requirements.txt`
4. (Optional) To use PostgreSQL instead of the default SQLite file, set `DATABASE_URL` to a SQLAlchemy URL for it. The compose database uses user, password and db name `app` on port 5432, and the psycopg (v3) driver is installed.
5. Apply the schema, which the app never creates at startup: `cd backend && .venv/bin/alembic upgrade head`
6. Start the API: `cd backend && .venv/bin/uvicorn app.main:app --reload`
7. In another terminal, install the frontend: `cd frontend && npm install`
8. Start the frontend dev server: `cd frontend && npm run dev`. The frontend calls `http://localhost:8000` unless `VITE_API_BASE_URL` is set at build time.
9. If the browser blocks API calls with a CORS error, set `ALLOWED_ORIGINS` (comma-separated) for the backend to include the Vite dev server origin.
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one APIRouter per component in app/routers/, included in app/main.py. Request bodies are Pydantic models and DB access goes through the `get_db` session dependency.
- Schema changes go through Alembic migrations only. `create_all` is never called at startup.
- Every API route depends on `auth.require_custom_header`. The frontend sends `X-Requested-With: pms` on non-GET/HEAD requests and includes the session cookie (`credentials: 'include'`).
- Role-based access uses `auth.require_role(...)` dependencies. The employee routes require `hr_admin`, and the lookup lists require any signed-in employee.
- Validation failures return 422 with a body of the form `{"errors": {field: message}}`, one plain-English message per field. Login failures return a single generic 401 message.
- Models use UUID primary keys, timezone-aware UTC timestamps and lower-cased work emails. Audit events are recorded in `audit_event`.
- Frontend: TypeScript with the `@/` alias for `src/`, and Tailwind classes driven by brand CSS variables (`var(--brand-*)`).
- Frontend: screens live in `src/screens/`, the routes and shell in `App.tsx`, and all API calls go through `apiFetch` in `src/lib/api.ts`, which throws `ApiError` with the HTTP status.
- Vitest tests sit beside the code they cover (`*.test.ts(x)` under src/). Playwright specs live in `e2e/`.
- Code is formatted and linted with Prettier/ESLint (frontend) and Ruff (backend).
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| API errors about missing tables on first run. | The app does not create its schema at startup. Run `alembic upgrade head` in backend/ against the same `DATABASE_URL` (the default is sqlite:///./app.db). |
| The browser blocks frontend calls to the API with a CORS error. | Set `ALLOWED_ORIGINS` (comma-separated) for the backend to include the frontend's origin, then restart uvicorn. |
| POST/PATCH requests from curl or other clients are refused even with a valid session. | All routes require a custom header. Send `X-Requested-With: pms`, as the frontend's `apiFetch` does. |
| Playwright cannot start the backend web server. | The e2e config runs `../backend/.venv/bin/python`. Create backend/.venv and install requirements.txt into it, or set `E2E_BASE_URL` to test a running app instead. |
| `npm run build` succeeds but `npm run typecheck` reports errors. | This is expected: the build does not typecheck. Fix the reported types (often an untyped `useState({})`) before treating the code as maintained. |
| The deployed or built frontend calls localhost instead of the real API. | `VITE_API_BASE_URL` is inlined at build time. Set it before running `npm run build`. |
| Chromium crashes during e2e runs inside Docker. | The config already passes `--disable-dev-shm-usage`. If crashes continue, give the container more shared memory. |
| `pytest` fails with `cannot import app`. | Run pytest from the backend/ directory so pytest.ini (`pythonpath = .`) is picked up. |
