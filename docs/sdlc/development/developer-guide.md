<!-- sdlc:auto:start overview -->
Performance management System (PMS) is a monorepo generated by the Quorq AI SDLC platform with two applications. `frontend/` is a Vite + React 19 single-page app written in TypeScript. It uses React Router 7, TanStack Query, react-hook-form and Tailwind CSS 4. Its screens are sign-in, set-password, my performance, goals, reviews, 1:1 check-ins, people and my profile. `backend/` is a FastAPI 0.115 service on SQLAlchemy 2 and Pydantic 2, with schema changes managed by Alembic migrations. Its routers cover auth and sessions, employees and invitations, goals and alignment, praise feedback, profile and photos, HR settings, questionnaires and rating scales, review periods, self-reviews, and 1:1s with action items. It also exposes a `/health` probe. The backend uses SQLite (`./app.db`) unless `DATABASE_URL` is set; `docker-compose.yml` provides PostgreSQL 16 and Redis 7 for local use. The root README still says the backend has only a health check, but the code now includes all of these routers. On pushes to `main`, a GitHub Actions workflow builds the backend Docker image and pushes it to ECR, and deploys the frontend build to AWS Amplify.

<!-- sdlc:auto:start prerequisites -->
- Node.js with npm (the frontend uses Vite 6, React 19 and TypeScript 5.6)
- Python 3.12 (the version used by backend/Dockerfile)
- pip and the Python venv module (the Playwright config expects backend/.venv)
- Docker with Docker Compose (optional: for local PostgreSQL 16 and Redis 7, and for building the backend image)

<!-- sdlc:auto:start setup -->
1. cd backend
2. python -m venv .venv
3. source .venv/bin/activate
4. pip install -r requirements.txt
5. alembic upgrade head   # creates the schema; the app never calls create_all at startup. Without DATABASE_URL this targets the default SQLite ./app.db
6. uvicorn app.main:app --reload   # API on http://127.0.0.1:8000, check /health
7. (optional, new terminal, from the repo root) docker compose up -d   # starts Postgres (user/password/db: app) on 5432 and Redis on 6379; then point DATABASE_URL at Postgres and rerun alembic upgrade head
8. cd frontend
9. npm install
10. npm run dev
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Backend: one APIRouter per feature area in app/routers/, each registered in app/main.py. Sub-resources are nested under the parent path (for example /goals/{goal_id}/progress and /one-on-ones/{id}/action-items).
- Validation errors return HTTP 422 as {"errors": {field: "English message"}}. Handlers build this with an `_invalid(errors)` helper, and a global RequestValidationError handler uses the same shape.
- Authorization uses FastAPI dependencies: `auth.current_employee`, `auth.require_role(...)` for roles employee, manager, hr_admin and executive, and `raise auth.PolicyRefusal` for denials. Every request also passes the app-wide `auth.require_custom_header` dependency.
- Partial updates check `body.model_fields_set`, so only the fields actually sent are validated and changed.
- Models use UUID primary keys and timezone-aware UTC timestamps (`datetime.now(UTC)`). Goals are soft-deleted via `deleted_at`, and leavers are deactivated rather than removed.
- Significant changes append AuditEvent rows; existing audit rows are never updated or deleted.
- Questionnaire edits create a new immutable version, and self-reviews store a snapshot of their questions and scale labels.
- HR-configurable behaviour is stored in system_setting rows and read via `auth.get_setting`, not hard-coded.
- Schema changes go only through numbered Alembic migrations (`NNNN_description.py`); the app never calls `create_all` at startup.
- Routers that would import each other circularly use function-local imports instead.
- Code comments and docstrings reference requirement IDs (US-xxx, AC-xxx, NFR-xxx).
- Frontend: TypeScript with the `@/` alias pointing at `src/`. Screens live in src/screens/ (PascalCase) and shared code in src/lib/ (camelCase). Data access goes through TanStack Query hooks in lib/.
- Styling uses Tailwind classes plus brand CSS variables such as `var(--brand-radius)` and `var(--brand-fg)`, defined in index.css and brand.ts. The interface is English-only.
- Frontend tests: component tests are *.test.tsx files beside the code they cover; Playwright specs are *.spec.ts files in e2e/.
- Code style is enforced by ESLint (with eslint-config-prettier) and Prettier on the frontend, and by Ruff on the backend. The platform runs `npm run lint` as a gate, so it should stay green.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| `pytest` fails with `ModuleNotFoundError: No module named 'app'`. | Run pytest from inside backend/. pytest.ini sets `pythonpath = .` only relative to that directory. |
| API calls fail because tables don't exist. | Run `alembic upgrade head` from backend/ against the same DATABASE_URL the app uses. The app never creates tables at startup. |
| The browser blocks frontend calls to the API with CORS errors. | Set ALLOWED_ORIGINS (comma-separated) to the frontend's origin. It is read in app/config.py and applied by the CORS middleware in main.py. |
| API requests are rejected even though you are signed in. | Every route depends on `auth.require_custom_header`, so requests must carry the header it expects. Send them through the frontend API client in src/lib/api.ts rather than calling the API by hand without that header. |
| `npm run test:e2e` cannot start the backend web server. | The Playwright config runs `../backend/.venv/bin/python -m uvicorn ...`. Create backend/.venv and install requirements.txt into it first, then run `npm run test:e2e:install` to fetch Chromium. |
| Vitest fails on Playwright fixtures. | Vitest only collects src/**/*.{test,spec}.{ts,tsx}. Keep Playwright specs in e2e/ and run them with `npm run test:e2e`. |
| `npm run build` succeeds but `npm run typecheck` reports errors. | This is expected: the build does not typecheck. Fix the reported types, often an untyped `useState({})` that is later read for named fields. |
| A built frontend calls localhost instead of the deployed API. | VITE_API_BASE_URL is inlined at build time. Set it when running `npm run build`, as deploy.yml does. |
| Need Postgres instead of the default SQLite ./app.db. | Run `docker compose up -d`, which provides user, password and database `app` on port 5432. Set DATABASE_URL to that server and rerun migrations. |
| Security concern: API secret key values are committed in .github/workflows/deploy.yml and inlined into the frontend bundle. | Treat these values as public. Move them to repository secrets or variables, and don't rely on a key baked into client-side code for security. |
<!-- sdlc:auto:end troubleshooting -->
