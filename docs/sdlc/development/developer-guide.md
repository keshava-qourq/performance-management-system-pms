<!-- sdlc:auto:start overview -->
Performance management System (PMS) is a two-app monorepo generated by the Quorq AI SDLC platform. `frontend/` is a Vite + React 19 single-page app (React Router 7, Tailwind CSS 4, TypeScript). Per its README, its approved screens run on seeded sample data and are not yet wired to the API. `frontend/src/lib/api.ts` provides an `apiFetch` helper as the place to add real API calls later. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2 and Pydantic 2. It defaults to a local SQLite database (`sqlite:///./app.db`) and can be pointed at PostgreSQL through `DATABASE_URL`. Right now it exposes only `GET /health`, which returns `{"status": "ok", "services": ...}`. No data models or routers are implemented yet. Tables are created from the models on startup with no migrations. `docker-compose.yml` provides optional local PostgreSQL 16 and Redis 7 containers. The backend Dockerfile builds a Python 3.12 image that serves the app on port 8000.
<!-- sdlc:auto:end overview -->

<!-- sdlc:auto:start prerequisites -->
- Node.js with npm (for the Vite/React frontend)
- Python 3.12, the version used by backend/Dockerfile, with pip and venv
- Docker and Docker Compose (optional: for the PostgreSQL/Redis containers and the backend image)
- Playwright Chromium browser (only for e2e tests; installed via `npm run test:e2e:install`)
<!-- sdlc:auto:end prerequisites -->

<!-- sdlc:auto:start setup -->
1. cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt
2. cd backend && .venv/bin/python -m uvicorn app.main:app --reload   # API on http://localhost:8000 using SQLite ./app.db
3. cd frontend && npm install
4. cd frontend && npm run dev   # Vite dev server (http://localhost:5173, the origin the backend allows by default)
5. Optional, to use PostgreSQL instead of SQLite: docker compose up -d, then start the backend with DATABASE_URL pointing at the compose database (user/password/db `app`, port 5432; psycopg 3 is the installed driver)
<!-- sdlc:auto:end setup -->

<!-- sdlc:auto:start conventions -->
- Frontend imports use the `@/` alias for `frontend/src` (configured in vite.config.ts and tsconfig.json).
- TypeScript runs in `strict` mode, but with `noImplicitAny` and `strictNullChecks` turned off.
- Vitest component tests live beside their components under `src/` as `*.test.ts(x)` or `*.spec.ts(x)`. Playwright specs live only in `e2e/`.
- Styling uses Tailwind CSS 4 via the @tailwindcss/vite plugin. Formatting is Prettier, and linting is ESLint 9 with typescript-eslint and the react-hooks plugin.
- Screens render seeded sample data. Wire them to the backend one at a time through `apiFetch` in `src/lib/api.ts`, which reads `VITE_API_BASE_URL` (default http://localhost:8000) and sends `VITE_API_SECRET_KEY` as a Bearer token if set.
- Backend configuration comes from environment variables read with os.getenv: `DATABASE_URL` (default sqlite:///./app.db) and `ALLOWED_ORIGINS` (comma-separated, defaulting to the Vite dev origins on port 5173).
- Backend layering: models subclass `app.database.Base` in models.py, Pydantic schemas go in schemas.py, and there is one router per component in `app/routers/`. Generated routes return a typed `StubResponse` until they are implemented.
- DB sessions are request-scoped through the `get_db` dependency. Tables are created with `Base.metadata.create_all` on startup (no Alembic migrations yet).
- Backend code is linted and formatted with Ruff. Test dependencies live in requirements.txt, not a separate file.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| The browser blocks frontend calls to the API with a CORS error. | By default the backend only allows http://localhost:5173 and http://127.0.0.1:5173. If the frontend runs on another origin, set ALLOWED_ORIGINS (comma-separated) before starting uvicorn. |
| `npm run build` succeeds but `npm run typecheck` fails. | This is expected: `vite build` does not typecheck. Fix the reported types; the frontend README notes untyped `useState({})` as the usual cause. |
| `npm run test:e2e` fails to start the backend web server. | Playwright runs `../backend/.venv/bin/python`. Create the venv and install dependencies first: `cd backend && python3 -m venv .venv && .venv/bin/pip install -r requirements.txt`. Also run `npm run test:e2e:install` to fetch Chromium. |
| pytest fails with `ModuleNotFoundError: No module named 'app'`. | Run `pytest` from the `backend/` directory, so that pytest.ini (`pythonpath = .`) is applied. |
| The backend can't connect after pointing DATABASE_URL at PostgreSQL. | Start the database with `docker compose up -d` and use the compose credentials (app/app, database `app`, port 5432). Unset DATABASE_URL to fall back to the local SQLite file. |
| The frontend fails to resolve `@/App`, or the README's `src/screens/` folder is missing. | `main.tsx` imports `@/App` and the frontend README describes `src/screens/` and `src/lib/brand.ts`, but none of these appear in the file tree. Restore or generate those files before running or building. |
| Data disappears or the schema doesn't update after model changes. | Tables are only created with create_all on startup, and existing tables are not altered. Delete `backend/app.db` while in development, or add Alembic migrations as the main.py comment advises. |
<!-- sdlc:auto:end troubleshooting -->
