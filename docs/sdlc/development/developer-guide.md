<!-- sdlc:auto:start overview -->
Performance management System (PMS) is a two-app monorepo generated by the Quorq AI SDLC platform. `frontend/` is a Vite + React 19 single-page app using TypeScript, Tailwind CSS v4, React Router 7 and TanStack Query. Its screens are My performance, Goals, Reviews, 1:1 check-ins, People and My profile, plus sign-in and set-password pages. `backend/` is a FastAPI 0.115 service using SQLAlchemy 2 and Alembic migrations. It exposes routers for auth/sessions, employees (the HR directory, invitations, password resets and deactivation), goals (alignment, progress, comments and team view), feedback/praise with a personal dashboard, the self-service profile with photo upload via Pillow and app/storage.py, and HR settings. The backend uses SQLite (`./app.db`) by default and switches to PostgreSQL 16 when `DATABASE_URL` is set. `docker-compose.yml` provides Postgres and Redis for local use. Pushes to `main` trigger a GitHub Actions workflow that pushes the API image to AWS ECR and publishes the frontend to AWS Amplify. Note that the READMEs predate some of the code: the backend is no longer health-check only, and `src/lib/api.ts` calls the real API.

<!-- sdlc:auto:start setup -->
1. cd backend
2. python -m venv .venv
3. .venv/bin/pip install -r requirements.txt
4. .venv/bin/alembic upgrade head
5. .venv/bin/uvicorn app.main:app --reload
6. In a second terminal: cd frontend
7. npm install
8. npm run dev
9. Optional, to use Postgres instead of SQLite: run `docker compose up -d` from the repo root, then set DATABASE_URL to point at the `app` database before running migrations and the server

<!-- sdlc:auto:start conventions -->
- Backend: one APIRouter per component in app/routers/, all registered in app/main.py.
- The schema changes only through Alembic migrations; there is no create_all at startup.
- Validation errors return HTTP 422 with the body {"errors": {field: "English message"}}. Routers share an `_invalid` helper for this.
- Authorization goes through `auth.current_employee` and `auth.require_role(...)` dependencies. Refusals raise `auth.PolicyRefusal`.
- Roles are employee, manager, hr_admin and executive.
- Every request depends on `auth.require_custom_header`. The frontend sends `X-Requested-With: pms` on every non-GET request alongside the session cookie, and uses `credentials: 'include'`.
- Sensitive actions (goal changes, password events, invitations, deactivation, settings) append an AuditEvent row. Audit rows are never updated or deleted.
- Models use UUID primary keys and timezone-aware UTC timestamps.
- Goals are soft-deleted via `deleted_at`. Goal progress is typed in by a person and never calculated.
- HR-configurable values are stored as `system_setting` rows and read with `auth.get_setting`.
- Frontend: the `@/` import alias maps to `src/`.
- Styling uses Tailwind with brand CSS variables such as `var(--brand-...)`, defined in index.css and brand.ts.
- All HTTP calls go through `apiFetch` in src/lib/api.ts. The base URL comes from `VITE_API_BASE_URL`, defaulting to http://localhost:8000.
- Unit tests sit beside the code they cover as `*.test.tsx`. Playwright specs live in `frontend/e2e/`.
- The interface is English-only: `<html lang="en">` is set unconditionally.
- TypeScript runs in strict mode, but with noImplicitAny and strictNullChecks turned off.
<!-- sdlc:auto:end conventions -->

<!-- sdlc:auto:start troubleshooting -->
| Problem | Solution |
|---|---|
| API errors about missing tables on a fresh clone. | Run `alembic upgrade head` from backend/. The app never creates tables itself. Without DATABASE_URL, migrations target ./app.db (SQLite). |
| Browser requests from the SPA are blocked by CORS. | Set ALLOWED_ORIGINS (comma-separated, read in app/config.py) to include the frontend's origin, then restart uvicorn. |
| POST, PATCH, PUT or DELETE requests from curl or other tools are refused. | Add the header `X-Requested-With: pms` and send the session cookie returned by POST /auth/login. |
| The frontend calls http://localhost:8000 in a deployed build. | Set VITE_API_BASE_URL at build time. Vite inlines it into the bundle. |
| `npm run test:e2e` fails to start the backend web server. | Create backend/.venv and install backend/requirements.txt into it. Playwright runs `.venv/bin/python -m uvicorn` from backend/. |
| `pytest` cannot import `app`. | Run pytest from the backend/ directory so pytest.ini (pythonpath = .) is picked up. |
| `npm run build` succeeds but `npm run typecheck` reports errors. | This is expected: the build does not typecheck. Fix the reported types before relying on tsc. Untyped `useState({})` is a common cause. |
| Login keeps failing for a correct password. | The account may be temporarily blocked after too many failed attempts (settings `login_max_failed_attempts` and `login_block_minutes`), or it may be deactivated or not yet active. Wait out the block, or have an HR Admin check the account. |
| deploy.yml hardcodes VITE_API_SECRET_KEY and NEXT_PUBLIC_API_SECRET_KEY in the frontend build env. | Anything passed as a VITE_ variable is inlined into the public bundle, so treat this value as non-secret. Move real secrets out of the workflow and frontend build. |
